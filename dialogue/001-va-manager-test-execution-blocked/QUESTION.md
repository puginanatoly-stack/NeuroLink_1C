## 4. Симптомы (главная проблема)

1. **Ручной запуск** `1cv8c.exe ENTERPRISE /F <база> /N NeuroLink /P NeuroLink /Execute vanessa-automation.epf /C "StartFeaturePlayer;VAParams=..."`:
   - VA-менеджер открывает главное окно базы, «работает» ~3–5 минут, **exit 0**, но: НЕТ текстового лога, НЕТ status.log, НЕТ JUnit — сценарии не выполняются. ЖР базы: сеанс открылся и закрылся без ошибок, никаких действий.
   - Без флага `/TestManager` процесс зависал (не завершался), приходилось убивать.
2. **vanessa-runner**: `vrunner vanessa --settings vrunner.json` → база открывается, но вывод: «Ошибка - фоновые/регламентные задания не найдены - не удалось получить файл статуса», «Внимание, сеанс 1С:Предприятие завершился аварийно. Возможно, зависло фоновое задание». Отчётов нет.

Итог: **VA-менеджер не выполняет ни одного шага/сценария, хотя обработка открывается и база доступна.**

## 5. Наблюдения и уже проверенные вещи

- **VanessaExt (внешняя компонента) НЕ установлена** — `QuietInstallVanessaExt` падала (VA завершалась с «Сообщение не отображено» в /Out-логе). В системе dll компоненты нет. Сейчас в VAParams компонента отключена.
  - Обработка установки `lib\CF\InstallVanessaExt\Ext\ManagedApplicationModule.bsl` принимает `AddinPath` (архив компоненты) + `LogPath` и ставит через `УстановитьВнешнююКомпоненту`. Т.е. VA где-то сама скачивает архив. **Где именно — НЕ найдено** (в исходниках lib/CF/83 текст `AddinPath`/`InstallVanessaExt` отсутствует, URL компоненты не найден).
  - Репо `Pr-Mex/VanessaExt` на GitHub НЕ существует (404). Компонента, вероятно, скачивается с сайта VA / bit-erp / другого места.
- Шаги сценария (открытие разделов) — стандартные, должны быть в библиотеке VA без компоненты, но это не проверено, т.к. до выполнения дело не доходит.
- Кириллица в путях ломается при передаче через консоль/Start-Process → используются короткие имена (`C:\Users\90C5~1\...`, `C:\PERSON~1\...`).
- База открывается только тонким клиентом `1cv8c` + `/N /P`; `/F` с полным путём (кириллица) не работает, `/IBName` работает.
- `vrunner vanessa --help` падает с ошибкой парсинга `cmdline.os` (вероятно, конфликт версий пакетов oscript — после `opm install add`), но сам `vrunner vanessa` запускается.

## 6. Гипотезы (для проверки аналитиком)

1. **VanessaExt обязательна** для StartFeaturePlayer даже на простых шагах — без неё VA не инициализирует выполнение. Нужно: найти источник компоненты и установить вручную, затем включить `ИспользоватьКомпонентуVanessaExt=true`.
2. **Менеджер VA должен запускаться ТОЛСТЫМ клиентом** (`1cv8.exe`, не `1cv8c`) или с обязательным `/TestManager` — тонкий клиент в режиме ENTERPRISE недостаточен для управления тест-клиентами.
3. **Тест-клиент не запускается** VA-менеджером (VA ждёт подключения клиента, потом падает). В VAParams клиенты заданы, но признаков запуска второго 1cv8c процесса не наблюдалось.
4. **Проблема с параметрами `StartFeaturePlayer` + VAParams** (неверный ключ структуры, VA не видит `КаталогФич` и молча завершается).
5. **Файловая база + тонкий клиент + фоновые задания**: сообщение vrunner «фоновые/регламентные задания не найдены» — возможно, VA использует фоновые задания для статуса, а они отключены/недоступны в файловой базе.
6. Конфликт версий пакетов oscript после установки `add` (cmdline) — вторично, может мешать vrunner.

3. Почему vrunner сообщает про фоновые/регламентные задания и как это обойти для файловой базы.
4. Минимальный рабочий набор шагов/конфигурации для первого прогона BDD на этой базе.

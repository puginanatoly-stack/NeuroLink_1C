# /jira-create-task — массовое создание задач Jira

Создаёт задачи в Jira из списка строк. Шаблон одобрен пользователем
(эталон: `PROJ-1`/`PROJ-2`): проект **`<ключ проекта>`**, тип **«Задача»** (id 3),
приоритет **«Основной»**, reporter=assignee=**`<username>`**, **Epic Link `<PROJ-N>`**,
**текущий спринт** (актуализировать id при смене спринта).
Статус при создании — «Сделать» (стартовый в проекте; проверить точное имя стартового статуса в вашей Jira).

## Параметры

| Параметр | Описание |
|----------|----------|
| `TasksFile` | UTF-8 файл, **одна задача на строку** |
| `Summary` | Создать одну задачу с этим заголовком |
| `NoSprint` | Не добавлять в спринт |

```powershell
python ".opencode/skills/jira-create-task/scripts/jira-create-tasks.py" `
  -TasksFile "список.txt"          # пачка задач
python ".../jira-create-tasks.py" -Summary "Описать задачу"   # одна
```

## Что делает

1. `POST /rest/api/2/issue` — создаёт задачу (summary = строка, description =
   строка + пометка «Задача создана из списка работ…», эпик из шаблона).
2. `POST /rest/agile/1.0/sprint/<id>/issue` — добавляет в текущий спринт.
3. Печатает ключи (`PROJ-xxxxx`).

## Важные грабли

- **Тип обязателен** в API (пусто нельзя): использовать **id 3** («Задача»),
  НЕ имя — по имени есть дубли («Задача» id 3 и 10401), Jira берёт не тот и отвечает
  «Выбранный тип запроса недействителен».
- **Спринт нельзя задать при создании** (поле `customfield_10005`) — API отвечает
  «ожидается числовое значение» на любой формат. Добавление — только Agile-эндпоинтом
  `/rest/agile/1.0/sprint/{id}/issue` после создания.
- **Custom screen-only fields** (project-specific `customfield_*`) —
  не на экране создания, API их не принимает («not on the appropriate screen»).
  Их выставляет пользователь в UI после создания (сверить по эталонной задаче своего проекта).
- Служебные `customfield_*` (авто-сводка devStatus и т.п.) — не контент; не трогать.
- Jira внутри сети — **обходить прокси** (`urllib.request.ProxyHandler({})`), иначе 502.
- Кириллица: слать body в UTF-8 байтах, `Content-Type: application/json; charset=utf-8`.
- `issuetype = "Задача"` в JQL может не матчиться по имени — сверять по id.

## Актуализация

При смене шаблона (проект/тип/эпик/спринт/пользователь) — править константы в
`scripts/jira-create-tasks.py` и этот файл. Текущий спринт брать из эталонной задачи:
`GET /rest/api/2/issue/<PROJ-N>?fields=customfield_10005` → `id=...`.

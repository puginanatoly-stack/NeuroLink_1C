# /xdto-graph — полный интерактивный граф XDTO-пакета

Читает `Ext/Package.bin` Designer-выгрузки (это XML с UTF-8 BOM) и строит
**граф всей схемы**: каждый тип — узел, каждая ссылка свойства на другой тип —
ребро. Результат — самодостаточный HTML на vis.js (force-физика, поиск,
фильтры, хабы, клик-детали), открывается в браузере без установки.

## Параметры

| Параметр | Обязательный | Описание |
|----------|--------------|----------|
| `PackagePath` | да | Каталог пакета (`XDTOPackages/<Имя>/`), путь к `Ext/Package.bin` или к `<Имя>.xml`-дескриптору. Псевдоним — `-Path` |
| `OutFile` | нет | Куда писать HTML (UTF-8 BOM). По умолчанию — `<Package.bin_dir>/<Имя>.graph.html` |
| `MinDegree` | нет | Скрыть типы, на которые ссылаются реже N раз (по in-degree) |
| `Title` | нет | Заголовок страницы / подпись пакета (по умолчанию — имя пакета) |

```powershell
python ".opencode/skills/xdto-graph/scripts/xdto-graph.py" `
  -PackagePath "src/XDTOPackages/EnterpriseData_2_7_1" `
  -OutFile "docs/graph-enterprisedata-2.7.1.html"
```

## Что получается

- **Узлы** (типы): объектные — синие квадраты, перечисления — янтарные круги,
  атомарные/ссылочные (`ТипСумма`, `СправочникСсылка.*`, `ТипСсылка`) — бирюзовые.
  **Размер узла пропорционален числу ссылок на него** → хабы видны сразу.
- **Рёбра**: направленные (свойство → тип значения), толщина по числу свойств,
  подсказка при наведении — через какие свойства связаны.
- **Панель справа**: поиск по имени (Enter — выделить/фокус), фильтры по классу узла,
  топ-10 хабов, при клике на узел — его тип/свойства/связи.
- **Счётчики**: объектных типов / перечислений / атомарных / рёбер, namespace, импорты.

## Типичный workflow

1. `/xdto-info src` — какие пакеты есть (имя, типы, namespace)
2. `/xdto-graph <пакет>` — весь пакет целиком: хабы, корневые точки входа, связи
3. `/xdto-info <пакет> -Name <Тип> -Depth 2` — структура конкретного типа для кода
4. `/xdto-decompile <пакет> -OutFile <файл.xsd>` — схема наружу контрагенту

## Как это устроено

`Package.bin` — XML (namespace `http://v8.1c.ru/8.1/xdto`): `<valueType>` (перечисления
и атомарные/ссылочные типы, в т.ч. `СправочникСсылка.*`), `<objectType>` со свойствами,
`<import>`. Скрипт нормализует namespace-префиксы по всему документу (свой пакет /
импорт / `xs:`), агрегирует параллельные рёбра (несколько свойств → один тип),
считает in-degree (хабы) и корневые объекты (in-degree = 0), генерирует HTML.

## Примечания

- MCP-граф (`1c-graph-metadata-mcp`) видит пакет только как узел `ПакетыXDTO.<Имя>`
  — внутренности не разбирает. Для уровня типов нужен этот скилл (или xdto-info).
- Большие пакеты (сотни типов): используй `-MinDegree`, чтобы убрать шум, либо
  фильтры на странице. Результат из ~300 узлов / ~500 рёбер рендерится нормально.
- Рабочий пример (одобрен 2026-08-26): `docs/graph-xdto-enterprisedata-2.7.1-full.html`.

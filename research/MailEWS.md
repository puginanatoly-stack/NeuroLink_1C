# MailEWS — почта Exchange из CLI по EWS

- **Что это:** чтение почтового ящика Exchange по **EWS** из командной строки — без браузера и без
  автоматизации OWA. Плюс подготовка **черновиков** ответов (отправка не выполняется).
- **Где реализация:** скилл [`skills/mail-ews/`](../skills/mail-ews/) этого репозитория
  (`SKILL.md` + `scripts/mail_ews.py`). Пути внутри `SKILL.md` — под машину оператора.
- **Проверено:** 2026-09-15 **на реальном сервере** (не по документации) — все команды прогнаны живыми.

## Стек

| Слой | Что | Версия | Чьё |
|---|---|---|---|
| Язык | Python | 3.14.6 | готовое |
| Клиент Exchange | **exchangelib** — SOAP-клиент EWS | 5.6.0 | готовое |
| HTTP | requests · urllib3 | 2.34.2 · 2.7.0 | готовое |
| NTLM / SSPI | requests-ntlm · pyspnego · sspilib | 1.3.0 · 0.12.1 · 0.5.0 | готовое |
| Прикладной код | `mail_ews.py` — CLI, доступ, чтение, отчёты, черновики | 485 строк, 19 функций | своё |
| Сервер | IIS 10 + Exchange 2016 (FES → BES), AD | — | готовое |

`exchangelib` — готовый аналог `glab` для Exchange: вся протокольная работа (SOAP-конверты, разбор XML,
объекты писем/папок/приглашений, Basic и NTLM) на ней. Своего кода — только обвязка.

В стеке нет: браузера, OWA-автоматизации, Node/JS, компилированных бинарей, OCR/vision, платных сервисов.
Транспорт — **только EWS**: IMAP/POP3/SMTP закрыты (993/143/587/25 не отвечают).

## Три условия доступа (иначе 401 / 403)

| # | Условие | Если нарушить |
|---|---|---|
| 1 | логин в форме **NetBIOS-домена**: `DOMAIN\user` | UPN (`user@domain`) и чужой домен → **401** |
| 2 | **явная версия EWS** `EXCHANGE_2016` | автоопределение exchangelib через `ConvertId` → **403** |
| 3 | `User-Agent` вида `Microsoft Office/16.0 (… Microsoft Outlook …; Pro)` | любой другой UA (`python-requests`, `Outlook/15.0.0.0`, `Entourage`, `Apple Mail`) → **403 с пустым телом** |

Ключевая находка — **сервер фильтрует EWS по allow-list `User-Agent`**. Это неочевидно: заголовки ответа
предлагают `Negotiate,NTLM,Basic`, Basic-логин проходит и на GET отдаёт 200, но любой SOAP-POST с «не-Office»
UA режется 403 с пустым телом — то есть ошибка выглядит как проблема прав, а не как фильтр клиента.
В exchangelib UA задаётся **атрибутом класса** `BaseProtocol.USERAGENT` (инстансный не читается).

## Диагностика кодов ответа

| Ответ | Что значит |
|---|---|
| **401** | неверная форма логина (UPN / не тот домен вместо `DOMAIN\user`) |
| **403, пустое тело** | отфильтрован `User-Agent` (allow-list) или не задана версия EWS |
| **403 → 500 + SOAP-fault** | запрос дошёл до приложения — ошибка прикладная, читать fault |
| **500 `ErrorImpersonateUserDenied`** | попытка импрешнейшна: в организации нет роли ApplicationImpersonation — читается только свой ящик |

## Грабли

- **Word/Outlook-письма несут тонны CSS.** Без вырезания `<style>/<script>/<head>` текст тонет в стилях,
  и письмо выглядит пустым. Резать эти блоки до `strip_html()`.
- **Письмо может быть не письмом.** Приглашение на встречу приходит как `MeetingRequest` (тела нет, только
  ссылка на конференцию). У `MeetingRequest` **нет `create_reply`** — отвечать либо обычным письмом
  организатору (это не тред приглашения), либо RSVP.
- **Штатный ответ на приглашение — RSVP** (Принять / Под вопросом / Отклонить); письмом он не заменяется.
- **Импрешнейшн** (`ExchangeImpersonation`) запрещён политикой → `ErrorImpersonateUserDenied`.
  Читается только собственный ящик.
- **Kerberos/SSO не всегда поднимается.** При наличии TGT `klist get HTTP/<host>` может вернуть
  `SEC_E_NO_CREDENTIALS`; тогда SSPI падает в NTLM с **кэшированными кредами Windows** и даёт 401 —
  это не признак неверного пароля, а признак того, что кэш домена не совпадает с паролем ящика.
- **Клиентская подпись Outlook** в серверно созданном черновике не появляется — вставляется вручную.
- **Команда `create_reply` для обычного письма** оставляет ответ в треде с историей (EWS `ReplyToItem`);
  для не-`Message` объектов путь другой, и тред теряется.
- **Безопасность:** пароль только в переменных окружения; неудачных попыток логина минимум (1–2),
  формы логина не перебирать — риск блокировки учётки; отправка письма не автоматизируется.

## Источники

- `exchangelib` 5.6.0 — поведение проверено вызовами на реальном сервере (2026-09-15):
  `Configuration`/`Version`/`BaseProtocol.USERAGENT`, `Message.create_reply` → `ReplyToItem`,
  `BaseReplyItem.save(folder=account.drafts)`.
- Диагностика доступа — серия сырых SOAP-запросов (`requests`, `curl --negotiate/--ntlm`) с разбором
  заголовков `WWW-Authenticate`, `X-DiagInfo`, `X-BEServer`.
- Реализация: [`skills/mail-ews/`](../skills/mail-ews/) (SKILL.md, scripts/mail_ews.py).
